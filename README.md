# yashirolang-IDE

**[yashirolang](https://github.com/yashirolang/yashirolang) のための、最小構成の統合開発環境です。**


> **言語処理系とは別のリポジトリです。**
> コンパイラ本体（`yashirolang`）は
> [yashirolang/yashirolang](https://github.com/yashirolang/yashirolang) にあります。
> この IDE は、そこで作った `yashirolang` を**外から呼ぶだけ**です。

---

## できること

| | |
|---|---|
| **フォルダを開く** | 左に木が出ます。枝は開いたときだけ読むので、大きな木でも重くなりません |
| **ファイルを作る** | `＋` で新規作成。`.ys` なら `def main()` の雛形が入ります |
| **編集** | Monaco（VS Code と同じエディタ）。`.ys` の色付け・補完・インデント |
| **確認** | `yashirolang --check` を走らせて、型の誤りだけを見ます（実行ファイルは作りません） |
| **エラー確認** | 「問題」タブに一覧が出ます。押すとその行へ飛びます。エディタにも波線が出ます |
| **実行** | コンパイルして、そのまま走らせます。出力も入力も下のパネルで |
| **デバッグ実行** | `-g` を付けてコンパイルし、lldb / gdb の上で走らせます |
| **ブレークポイント** | 行番号の左をクリック。続行・ステップオーバー / イン / アウト |
| **変数を見る** | 止まったところの変数が名前と値で並びます。`list` とクラスと `rc` は**開いて中身**が見えます（言語 **0.28.0** 以降） |
| **値をその場で** | 名前にマウスを当てると**いまの値**が出ます。行の右にも薄く並びます |
| **複数ファイル** | `import` した先にもブレークポイントを置けます。止まればそのファイルが開きます |
| **定義へ移動** | `F12`（`⌘`＋クリックでも）。`import` した先や標準ライブラリの中まで飛びます。`Alt+←` で戻ります |

## 必要なもの

| | |
|---|---|
| **yashirolang** | コンパイラ本体。`make install` 済み、または `build/yashirolang` があれば十分です（**変数を見るには 0.28.0 以降**） |
| **clang** | yashirolang がリンクに使います（[言語側の README](https://github.com/yashirolang/yashirolang#必要なもの) と同じ） |
| **Node.js 20 以上** | ソースから動かすときだけ |
| **lldb / gdb** | デバッグ実行のときだけ。macOS は `xcode-select --install` で入ります |

## 使ってみる

```bash
git clone https://github.com/yashirolang/yashirolang-IDE.git
cd yashirolang-IDE
npm install
npm start
```

起動したら **「フォルダを開く…」** で作業フォルダを選び、`＋` で `main.ys` を作って、
**▶ 実行** を押すだけです。

### コンパイラの見つけ方

IDE は次の順で `yashirolang` を探します。**ふつうは何も設定しなくて構いません。**

1. 設定（⚙）で指定した場所
2. `PATH` の上（`make install` した場合）
3. IDE の隣にあるソースの木（`../yashirolang/build/yashirolang`）

見つからないときは右下が赤くなります。⚙ →「選ぶ…」で実行ファイルを指してください。

> **ソースの木ごと移動しても動きます。**
> yashirolang は `runtime.a` と標準ライブラリの場所をビルド時に埋め込みますが、
> IDE は起動のたびに `PLC_RUNTIME_O` / `PLC_LIB_DIR` を組み立てて渡します。

## デバッグ実行について

**▶ 実行** ではなく **🐞 デバッグ** を押すと、`-g -O0` でコンパイルし直して
lldb（macOS）／ gdb（Linux）の上で走らせます。

| ボタン | 何をするか | キー |
|---|---|---|
| 🐞 デバッグ | 始める。**止まっているときに押すと続行**（VS Code と同じ） | `F5` |
| ⏵ 続行 | 次のブレークポイントまで走る | `F8` |
| ⏸ 一時停止 | **走っている最中に割り込んで、いまの行で止める** | `F6` |
| ⤼ ステップオーバー | 次の行へ（関数の中へは入らない） | `F10` |
| ⤓ ステップイン | 呼んでいる関数の中へ入る（**別のファイルでも**） | `F11` |
| ⤒ ステップアウト | いまの関数から出る | `⇧F11` |
| ■ 停止 | デバッグを終える | `⇧F5` |
| ● ブレークポイント | 行番号の左をクリック | `F9` |

⏵ と ⏸ は**同じボタン**です。走っている間は ⏸ に変わります
（ブレークポイントを置き忘れて走らせてしまっても、そこで止めて中を見られます）。

キーは**どこにカーソルがあっても**効きます（木でも出力欄でも）。
同じ指示が二重に届いても 2 歩進むことはありません
（返事が返るまで次を受け取らないため）。

止まると「デバッグ」タブに**呼び出し履歴**と**変数**が出ます。
プログラムの出力と入力は、止まっている間も「出力」タブでやり取りできます。

> **⚠️ 一時停止は「信号を送る」ことで実現しています。**
> デバッガはパイプで動かしているので端末がなく、Ctrl-C を渡せません。
> 走っている最中のデバッガは次の命令も読みません（実行中だからです）。
> そこで**対象プログラムへ直接 SIGINT を送り**、デバッガが
> 「signal SIGINT で止まった」と報告してくるのを、いつもの停止として扱います。
> 対象の番号は、デバッガの子孫（macOS は lldb → debugserver → 対象）から探します。
> lldb が「Process 1234 launched」と言うのは**止まったあと**なので、そこからは取れません。
> Windows では一時停止できません（送る手段がないため。■ 停止は使えます）。

### 呼び出し履歴を押すと、その枠の変数に切り替わります

```
呼び出し履歴                      変数 / 評価  #2 main.main
  #0 util.add   util.ys:2         引数
  #1 util.twice util.ys:6           （なし）
▸ #2 main.main  main.ys:5         ローカル変数
                                    x = 5
                                    y = 0
```

`#0` は止まった場所、`#2` は**呼んだ側**です。押すとそのファイルのその行が開き、
**その枠から見えている変数**に変わります（「渡す前の値は何だったか」を見るところ）。

### 変数（言語 0.28.0 以降）

```
変数 / 評価
   n    = 7                              int
   msg  = 0x0001 "hello"                 str
 ▸ xs   = 0x6000                         list[int]
 ▾ p    = 0x6000                         Point
     x  = 4
     y  = 5
```

- `int` / `float` / `bool` / 範囲型はそのまま数で、`str` は中身の文字列で出ます
- **`▸` を押すと開きます** — `list` は `data` / `len` / `cap`、クラスはフィールド、
  `rc[T]` は数え札（`strong` / `borrow`）まで見えます
- 下の欄に式を書くと、その場で評価します（`p->x`、`n + 1` など）
- **引数**と**ローカル変数**は分けて並びます。多いときは上の欄で名前を絞れます
- **名前にマウスを当てると、その場で値が出ます。**
  行の右にも薄く並ぶので、当てなくても目で追えます

> **⚠️ マウスを当てて読むのは「名前と `.` だけでできた式」に限っています。**
> `xs[i]` や `f()` は読みません。式を評価すると関数が動いてしまい、
> **見ただけのつもりがプログラムの状態を変えてしまう**からです。
> それらを見たいときは、下の評価欄に自分で書いてください。

> **⚠️ 変数が出ないときは 2 つのどちらかです。**
> ① コンパイラが **0.27.0 以前**（変数のデバッグ情報は 0.28.0 から）
> ② 最適化つきで建てた（デバッグ実行は `-O0` に固定しているので、ふつうは起きません）
> どちらの場合も、画面にその理由を出します。

## 複数のファイルで書く

```
myapp/
  main.ys        ← 入口（def main() があるファイル）
  util.ys        import util
  shapes/
    point.ys     import shapes.point
  deps/          ← ysm が置く（package.toml のある木）
```

**建てるのは入口のファイル 1 つだけです。** 処理系が `import` をたどって、
まとめて 1 つの実行ファイルにします（`.o` を別々に作って後で繋ぐ、ではありません）。
だから IDE 側も「どれを建てるか」を 1 つ決めれば済みます。

| | |
|---|---|
| **入口の決め方** | ① 「スケッチ →**このファイルを入口にする**」で指定したもの（フォルダごとに覚えます）<br>② いま開いている `.ys` に `def main(` があれば、それ<br>③ フォルダの中で `def main(` があるのが 1 つだけなら、それ |
| **いま何が入口か** | 画面のいちばん下に「入口: main.ys」と出ます。押すと切り替わります |

`util.ys` を開いたまま ▶ や 🐞 を押しても、建つのは `main.ys` です。

### 複数ファイルのデバッグ

**できます。** ブレークポイントは**どのファイルにでも**置けます。

- `util.ys` の行に ● を置いて 🐞 → その行で止まり、`util.ys` が開きます
- 呼び出し履歴は `util.add ← util.twice ← main.main` のように**ファイルをまたいで**並びます
- `F11`（ステップイン）で、`import` した先の関数の中へそのまま入れます
- **標準ライブラリの中にも入れます**（`strings.strip` の中で止まれます）。
  開いているフォルダの外なので、**読むだけのタブ**（🔒）で開きます

> **同じ名前のファイルが 2 か所にあると、どちらで止まるか決まりません。**
> デバッガはファイル**名**でしか場所を指せないからです
> （`-g` が入れるのはファイル名だけで、フォルダは入りません）。
> 黙って進まず、デバッグを始めるときに「2 か所にあります」と出します。

### import した先のエラー

「問題」一覧には、**import した先で出たエラー**も並びます。押すとそのファイルの
その行が開き、波線も付きます（直す場所はそこなので、そこへ連れて行きます）。

> **処理系は import した先のエラーを相対パスで返します**（`util.ys:2:14`）。
> IDE が入口のフォルダを基準に絶対パスへ直しているので、押せば開きます。

> **置けなかったブレークポイントには `○` が付きます。**
> その行が実行ファイルに入っていない — つまり**入口から `import` されていない
> ファイル**だ、という意味です。入口が合っているか確かめてください。

## ライブラリはどうなるか

`import` で使える物は 3 か所にあります。**探す順も処理系とまったく同じ**です。

| | どこ | どう置くか |
|---|---|---|
| ① **自分のファイル** | 入口の隣（`util.ys`） | `import util` と書くだけ |
| ② **外から入れた物** | `deps/`（パッケージマネージャ `ysm`） | `ysm add toml https://github.com/user/toml-pkg 1.2.0` |
| ③ **標準ライブラリ** | 処理系に付いてくる `lib/` | `import strings` と書くだけ |

**IDE 側ですることはありません。** `-I` も `deps` も自動で渡します
（`.ysbuild/` にビルドの中間物を置くのと同じで、設定はいりません）。
足したい場所があるときだけ、設定（⚙）の「追加の引数」に `-I 場所` と書きます。

左の下にある **「ライブラリ」** を開くと、いま `import` できる物が並びます。

```
▾ ライブラリ
  標準ライブラリ
    ◆ strings   ◆ io      ◆ dict    ◆ math
    ◆ json      ◆ http    ◆ frame   ◆ plot   …
  deps（ysm）
    ◆ toml
```

押すと中身が読めます（**読むだけ**です。書き換えは開いているフォルダの中だけ）。
定義へ移動（`F12`）とデバッグのステップインも、この中まで入っていきます。

> **`import strings` と `import 自分の strings.ys` がぶつかったら？**
> 処理系が**エラーにします**（どちらを優先する、という決まりを作らない設計です）。
> IDE も勝手に `-I` を足さないので、見えているものがそのまま処理系の答えになります。

### 標準ライブラリの場所

処理系に訊いています（`yashirolang --print-lib-dir`）。
⚙ の下に、いま使っている場所が出ます。

## 定義へ移動

`F12`（`⌘`＋クリックでも）で、名前の宣言へ飛びます。`Alt+←` で戻ります。

飛べるのは次の 3 つです。

| | 例 |
|---|---|
| 同じファイルの中 | 変数・引数・関数・クラス・フィールド |
| `import` した先 | `util.twice` → `util.ys` の `twice`／`import util` → `util.ys` の頭 |
| 型の書いてある変数のメンバ | `p: Point` の `p.x` → `class Point` の `x` |

> **式の型が要る名前は追いません。** `f().g` のような物は、
> 型推論をしないと `g` がどれか決まりません。
> **当てずっぽうで別の場所へ飛ばすのは、飛ばさないより悪い**ので、
> そういうときは「定義が分かりませんでした」と出して動きません。

名前の表は、**コンパイラ自身の字句解析器**（`yashirolang --dump-tokens`）に
乗せて作っています。構文解析器を IDE 側に書き直すと、言語が変わったときに
黙って食い違うからです。VS Code 拡張の言語サーバと**同じ表**なので、
どちらで開いても答えは同じです。

## 設定（⚙）

| | |
|---|---|
| コンパイラ | 空なら自動で探します |
| デバッガ | 空なら lldb / gdb を自動で探します |
| 最適化 | `-O0` … `-O3`。デバッグ実行のときは `-O0` に固定されます |
| 入口のファイル | 複数ファイルのときに建てるもの。空なら自動で決めます（下の節） |
| 追加の引数 | そのままコンパイラへ渡します（例: `--warn-own`、`-I lib`） |

| ビルドの前に保存する | 既定で入。Arduino と同じ挙動です |

設定は `~/Library/Application Support/yashirolang-ide/settings.json`
（Linux は `~/.config/yashirolang-ide/`）に置きます。

## 作りと、なぜそうしたか

```
src/
  main/            Electron の本体（ここだけが OS とファイルに触れます）
    main.js        窓を出して、画面からの依頼を受ける
    toolchain.js   コンパイラとデバッガを探して、環境変数を組み立てる
    build.js       --check とコンパイル
    run.js         出来た実行ファイルを走らせる
    debug.js       lldb / gdb を対話モードのまま動かす（変数の解析もここ）
    sources.js     ファイルの居場所を決める（import と同じ順で探します）
    symbols.js     定義へ移動と型の表示（--dump-tokens に乗ります）
    ysindex.js     トークン列から名前の表を作る（vscode 拡張と同じもの）
    diagnostics.js コンパイラの出力を「問題」一覧の形に直す
    files.js       フォルダの読み込みとファイルの作成（開いたフォルダの外は触らない）
    settings.js    設定の保存
    preload.js     画面に見せる窓口（これ以外は見せない）
  renderer/        画面（Node の力は持ちません）
    app.js         画面ぜんぶ
    yashirolang-language.js  Monaco に .ys を教える
test/
  smoke.js         起動から デバッグ実行 までの自己点検
```

**① コンパイラを組み込まず、外から呼ぶ。**
言語と IDE を別のリポジトリに分けている以上、IDE が言語の版に縛られてはいけません。
`yashirolang` を `--check` / `-g` 付きで呼ぶだけにして、
出力の**文字**（`error: ... --> file:line:col`）だけを頼りにしています。

**② デバッガは MI ではなく CLI を相手にする。**
`lldb-mi` は macOS に入っておらず、gdb の MI とも互換がありません。
「clang さえあれば動く」という言語側の方針に合わせて、
どの環境にも最初からある対話モードを使っています。
そのために落とし穴が 2 つあり、`src/main/debug.js` の頭に書いてあります。

**③ 画面から OS へは、`preload.js` に並べた関数だけ。**
`contextIsolation` は入れたままで、パスは必ず「開いているフォルダの中か」を確かめます。

## 自己点検

```bash
npm run smoke
```

仮のフォルダを作り、画面を実際に組み上げて
**開く → 確認 → エラー表示 → 実行 → 標準入力 → デバッグ実行 → ステップ →
変数を読む → 中身を開く → 値をその場で見る → 定義へ移動 → import した先で止まる →
呼び出し元の枠に切り替える → import した先のエラーへ飛ぶ →
走っている最中に一時停止する → 標準ライブラリの中へ入る**までを
人の代わりに押します（61 件）。
コンパイラやデバッガが無い環境では、その先を飛ばします。

```bash
YS_COMPILER=/path/to/yashirolang npm run smoke   # 別の版で試すとき
```
