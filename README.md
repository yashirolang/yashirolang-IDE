# yashirolang-IDE

**[yashirolang](https://github.com/yashirolang/yashirolang) のための、最小構成の統合開発環境です。**
Arduino IDE と同じで、覚えることは「**確認**」と「**実行**」の 2 つのボタンだけ。
そこにブレークポイントを置ける**デバッグ実行**が付いています。

```
┌──────────────────────────────────────────────────────────┐
│ ✔ 確認   ▶ 実行   ■ 停止  │  🐞 デバッグ  ⏵ ⤼ ⤓ ⤒     待機中 ⚙ │
├───────────┬──────────────────────────────────────────────┤
│ 📁 myapp  │ main.ys                                      │
│  ◆ main.ys│  1  def main() -> int:                       │
│  ◆ util.ys│  2      x: int = 1                           │
│  📄 README│ ●3      y: int = x + 2   ← 行番号の左で止める   │
│           │  4      print(str(y))                        │
│           ├──────────────────────────────────────────────┤
│           │ 出力 │ 問題 ① │ デバッグ                      │
│           │ 3                                            │
│           │ — 終了コード 0 —                              │
└───────────┴──────────────────────────────────────────────┘
```

> **言語処理系とは別のリポジトリです。**
> コンパイラ本体（`yashirolang`）は
> [yashirolang/yashirolang](https://github.com/yashirolang/yashirolang) にあります。
> この IDE は、そこで作った `yashirolang` を**外から呼ぶだけ**です。
> IDE を入れ替えても言語は変わらず、言語を更新しても IDE はそのまま使えます。

---

## できること

| | |
|---|---|
| **フォルダを開く** | 左に木が出ます。枝は開いたときだけ読むので、大きな木でも重くなりません |
| **ファイルを作る** | `＋` で新規作成。`.ys` なら `def main()` の雛形が入ります |
| **編集** | Monaco（VS Code と同じエディタ）。`.ys` の色付け・補完・インデント |
| **確認** | `yashirolang --check` を走らせて、型の誤りだけを見ます（実行ファイルは作りません） |
| **エラー確認** | 「問題」タブに一覧が出ます。押すとその行へ飛びます。エディタにも波線が出ます |
| **実行** | コンパイルして、そのまま走らせます。出力も入力も下のパネルで |
| **デバッグ実行** | `-g` を付けてコンパイルし、lldb / gdb の上で走らせます |
| **ブレークポイント** | 行番号の左をクリック。続行・ステップオーバー / イン / アウト |

---

## 必要なもの

| | |
|---|---|
| **yashirolang** | コンパイラ本体。`make install` 済み、または `build/yashirolang` があれば十分です |
| **clang** | yashirolang がリンクに使います（[言語側の README](https://github.com/yashirolang/yashirolang#必要なもの) と同じ） |
| **Node.js 20 以上** | ソースから動かすときだけ |
| **lldb / gdb** | デバッグ実行のときだけ。macOS は `xcode-select --install` で入ります |

## 使ってみる

```bash
git clone https://github.com/yashirolang/yashirolang-IDE.git
cd yashirolang-IDE
npm install
npm start
```

起動したら **「フォルダを開く…」** で作業フォルダを選び、`＋` で `main.ys` を作って、
**▶ 実行** を押すだけです。

### コンパイラの見つけ方

IDE は次の順で `yashirolang` を探します。**ふつうは何も設定しなくて構いません。**

1. 設定（⚙）で指定した場所
2. `PATH` の上（`make install` した場合）
3. IDE の隣にあるソースの木（`../yashirolang/build/yashirolang`）

見つからないときは右下が赤くなります。⚙ →「選ぶ…」で実行ファイルを指してください。

> **ソースの木ごと移動しても動きます。**
> yashirolang は `runtime.a` と標準ライブラリの場所をビルド時に埋め込みますが、
> IDE は起動のたびに `PLC_RUNTIME_O` / `PLC_LIB_DIR` を組み立てて渡します。

## デバッグ実行について

**▶ 実行** ではなく **🐞 デバッグ** を押すと、`-g -O0` でコンパイルし直して
lldb（macOS）／ gdb（Linux）の上で走らせます。

| ボタン | 何をするか | キー |
|---|---|---|
| 🐞 デバッグ | 最初のブレークポイントまで走る | `F5` |
| ⏵ 続行 | 次のブレークポイントまで走る | `F8` |
| ⤼ ステップオーバー | 次の行へ（関数の中へは入らない） | `F10` |
| ⤓ ステップイン | 呼んでいる関数の中へ入る | `F11` |
| ⤒ ステップアウト | いまの関数から出る | `⇧F11` |
| ● ブレークポイント | 行番号の左をクリック | `F9` |

止まると「デバッグ」タブに**呼び出し履歴**が出ます。押すとその行へ飛びます。
プログラムの出力と入力は、止まっている間も「出力」タブでやり取りできます。

> **⚠️ いまは変数の一覧が出せません。**
> yashirolang の `-g` は**行の情報だけ**を出し、変数のデバッグ情報（DWARF）は
> まだ出していないためです。値を見たいところでは `print(str(x))` を挟んでください。
> 言語側が変数情報を出すようになれば、この画面はそのまま埋まります。

## 設定（⚙）

| | |
|---|---|
| コンパイラ | 空なら自動で探します |
| デバッガ | 空なら lldb / gdb を自動で探します |
| 最適化 | `-O0` … `-O3`。デバッグ実行のときは `-O0` に固定されます |
| 追加の引数 | そのままコンパイラへ渡します（例: `--warn-own`、`-I lib`） |
| 文字の大きさ | |
| ビルドの前に保存する | 既定で入。Arduino と同じ挙動です |

設定は `~/Library/Application Support/yashirolang-ide/settings.json`
（Linux は `~/.config/yashirolang-ide/`）に置きます。

## 作りと、なぜそうしたか

```
src/
  main/            Electron の本体（ここだけが OS とファイルに触れます）
    main.js        窓を出して、画面からの依頼を受ける
    toolchain.js   コンパイラとデバッガを探して、環境変数を組み立てる
    build.js       --check とコンパイル
    run.js         出来た実行ファイルを走らせる
    debug.js       lldb / gdb を対話モードのまま動かす
    diagnostics.js コンパイラの出力を「問題」一覧の形に直す
    files.js       フォルダの読み込みとファイルの作成（開いたフォルダの外は触らない）
    settings.js    設定の保存
    preload.js     画面に見せる窓口（これ以外は見せない）
  renderer/        画面（Node の力は持ちません）
    app.js         画面ぜんぶ
    yashirolang-language.js  Monaco に .ys を教える
test/
  smoke.js         起動から デバッグ実行 までの自己点検
```

**① コンパイラを組み込まず、外から呼ぶ。**
言語と IDE を別のリポジトリに分けている以上、IDE が言語の版に縛られてはいけません。
`yashirolang` を `--check` / `-g` 付きで呼ぶだけにして、
出力の**文字**（`error: ... --> file:line:col`）だけを頼りにしています。

**② デバッガは MI ではなく CLI を相手にする。**
`lldb-mi` は macOS に入っておらず、gdb の MI とも互換がありません。
「clang さえあれば動く」という言語側の方針に合わせて、
どの環境にも最初からある対話モードを使っています。
そのために落とし穴が 2 つあり、`src/main/debug.js` の頭に書いてあります。

**③ 画面から OS へは、`preload.js` に並べた関数だけ。**
`contextIsolation` は入れたままで、パスは必ず「開いているフォルダの中か」を確かめます。

## 自己点検

```bash
npm run smoke
```

仮のフォルダを作り、画面を実際に組み上げて
**開く → 確認 → エラー表示 → 実行 → 標準入力 → デバッグ実行 → ステップ**
までを人の代わりに押します。コンパイラやデバッガが無い環境では、その先を飛ばします。
